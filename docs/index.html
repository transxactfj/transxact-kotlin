KOTLIN SDK

Payments made easy.
On your Kotlin server.

Take M‑PAiSA and MyCash payments in FJD with Transxact hosted Checkout Sessions. Create a session, send the Customer to its hosted page, and fulfil from a verified webhook.

implementation("io.transxact:transxact-kotlin:0.1.0")
01 — How it works

Server-side, with your secret key.

This is a JVM library for your Merchant backend (Java 11 or later). It holds your sk_ key, so it never belongs in an Android app. Mobile apps ask your backend, which uses this SDK.

CREATE

Start a Checkout Session

Call checkoutSessions.create with the amount in FJD cents and an idempotency key derived from your order.

REDIRECT

Send the Customer

Redirect them to the returned hostedUrl. They pick M‑PAiSA or MyCash and confirm on their phone.

FULFIL

Trust the webhook

Verify the Transxact-Signature header, then fulfil on checkout_session.succeeded. The redirect is only a hint.

1 · Your serverCreates the session with your key
2 · CustomerPays on the hosted page
3 · TransxactSends a signed webhook
4 · Your serverVerifies it and fulfils
02 — Quickstart

Four pieces of code.

Add the dependency, create a session, verify webhooks, and handle errors. Every call is a suspend function.

1 · Install

Add the library from Maven Central. It brings OkHttp and kotlinx.serialization with it.

Use a sk_test_ key while you build: Test mode simulates payments and moves no money.

// build.gradle.kts
dependencies {
    implementation("io.transxact:transxact-kotlin:0.1.0")
}

2 · Create a session

Amounts are FJD cents and must be under FJD 5,000.00. Send amount with currency, or a quote, never both.

The same idempotencyKey returns the original session, so a retry never charges twice. Without one, a random UUID is used.

val transxact = Transxact(System.getenv("TRANSXACT_SECRET_KEY"))

val session = transxact.checkoutSessions.create(
    CreateCheckoutSessionParams(
        amount = 5000, // FJD 50.00
        currency = "FJD",
        successUrl = "https://shop.example/return",
        cancelUrl = "https://shop.example/return",
        metadata = mapOf("orderId" to "9912"),
    ),
    idempotencyKey = "order-9912",
)
// Redirect the Customer to session.hostedUrl

3 · Verify webhooks

Pass the raw request body, exactly as received, not re-serialized JSON. Signatures older than 5 minutes are rejected.

Delivery is at least once, so record the ids you have handled and skip repeats. Your signing secret is in the dashboard’s Webhooks section.

// Ktor shown; any framework works if you read the raw body.
post("/webhooks/transxact") {
    val raw = call.receiveText()
    val ok = Webhooks.verifySignature(
        raw,
        call.request.header("Transxact-Signature") ?: "",
        System.getenv("TRANSXACT_WEBHOOK_SECRET"),
    )
    if (!ok) return@post call.respond(HttpStatusCode.BadRequest)

    val event = Webhooks.parseEvent(raw)
    if (event.type == "checkout_session.succeeded") {
        val session = event.checkoutSession() // fulfil once per event.id
    }
    call.respond(HttpStatusCode.OK)
}

4 · Handle errors

A non-2xx response throws TransxactApiException. Branch on code; the message is for logs.

If the request never got an answer, you get TransxactConnectionException. Retries are automatic, see below.

try {
    transxact.checkoutSessions.retrieve("cs_…")
} catch (e: TransxactApiException) {
    println("${e.statusCode} ${e.code}")
} catch (e: TransxactConnectionException) {
    // offline, DNS, TLS, timeout
}
03 — Safety rules

Built so the unsafe thing is hard to do.

These behaviours are part of the SDK’s design and are covered by its tests.

Server-side only

The client takes your sk_ key. Keep it in your server’s environment or secret store, never in a mobile app or the repository.

Verified webhooks

Webhooks.verifySignature checks HMAC-SHA256 over timestamp.payload with a constant-time compare and a 5-minute window.

Idempotent creates

Creating a session or invoice, and sending or voiding an invoice, always carry an Idempotency-Key. A retry replays the original.

Safe retries

Timeouts, network failures and HTTP 408, 429 and 5xx are retried with backoff (default 2 retries), honouring Retry-After.

Forward compatible

Statuses are plain strings and unknown fields are ignored, so a new status or field from the API never breaks an older SDK.

Don’t fulfil on the redirect

The Customer’s return is a hint, not proof. Fulfil from the webhook, or confirm with checkoutSessions.retrieve.

04 — API

One client, four resources.

Create Transxact once and share it. Money is always FJD cents (Long).

Transxact

The client. All resource calls hang off it.

ParameterWhat it does
apiKeyYour sk_test_… or sk_live_… key. The key picks Test or Live mode
baseUrlDefaults to https://api.transxact.io
maxRetriesRetries of a transient failure (default 2)
httpYour own OkHttpClient, for timeouts, proxies or logging

checkoutSessions

Collect one payment.

Method
create(params, idempotencyKey)Start a payment
retrieve(id)Fetch one
list(limit, cursor, status, from, to)Newest first; pass nextCursor as cursor
cancel(id)Cancel a pending session
pending→succeededfailedcancelled

invoices

Request payment with line items and a due date.

Method
create(params, idempotencyKey)Create a draft
send(id) / void(id)Send to the Customer, or void
retrieve(id) / list(limit, startingAfter)Fetch or page
retrievePdf(id)The PDF as bytes

merchants & payouts

Read-only account and settlement info.

Method
merchants.me()Tier, mode, balance, payout schedule
payouts.list(limit, startingAfter)Your Payouts
payouts.retrieve(id)One Payout

Webhooks

Hand-written helpers for incoming events.

Function
verifySignature(raw, header, secret)True only for a genuine, recent webhook
parseEvent(raw)An id, type and checkoutSession(). Call after verifying

Exceptions

Branch on the type and on code, never on the message.

TypeWhen
TransxactApiExceptionA 4xx or 5xx response. statusCode, code and the raw body are set
TransxactConnectionExceptionNo response at all: offline, DNS, TLS or timeout, after retries ran out

The full REST reference is at docs.transxact.io, and the README covers the rest.

05 — Try it

Run it against Test mode.

Use an sk_test_ key: sessions are simulated and no money moves. The repo’s smoke test creates, retrieves, lists and cancels a real Test mode session, and is skipped when no key is set.

TRANSXACT_SECRET_KEY="sk_test_…" ./gradlew test --tests "*SmokeTest*" -i
